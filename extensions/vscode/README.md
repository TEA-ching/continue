## KeypoolLive — Shared Encrypted API Key Vault

This fork adds **KeypoolLive**, a system that loads AI provider API keys from an encrypted vault file hosted at a public URL. Keys are shared across a team, rotated round-robin, and never stored in plain text in version control.

### How it works

1. An AES-256-CBC encrypted vault (`ai.json.enc`, produced with `openssl enc -aes-256-cbc -pbkdf2`) is hosted at a URL you control.
2. Continue fetches and decrypts the vault at startup using a secret you provide.
3. All models in the vault are injected into the Continue model selector automatically — no manual `config.yaml` entries per model needed.
4. Optionally, all requests are routed through a **Cloudflare AI Gateway** for unified logging, rate limiting, and caching.

### Configuration

Add a `keypoollive` block to `~/.continue/config.yaml`:

```yaml
keypoollive:
  vaultUrl: https://your-host/ai.json.enc # URL of the encrypted vault
  secret: <decryption-secret> # AES decryption passphrase
  useGateway: true # Route via Cloudflare AI Gateway
  gatewaySecret: cfut_xxxxxxxxxxxxxxxxxxxx # cf-aig-authorization token
  gatewayId: <your-cloudflare-gateway-id> # Cloudflare account/gateway ID
```

All fields can be overridden with environment variables (env takes precedence over YAML):

| YAML field      | Environment variable                        |
| --------------- | ------------------------------------------- |
| `vaultUrl`      | `KEYPOOL_LIVE_VAULT_URL`                    |
| `secret`        | `KEYPOOL_LIVE_SECRET`                       |
| `useGateway`    | `KEYPOOL_LIVE_USE_GATEWAY` (`true`/`false`) |
| `gatewaySecret` | `KEYPOOL_LIVE_GATEWAY_SECRET`               |
| `gatewayId`     | `KEYPOOL_LIVE_GATEWAY_ID`                   |

### Direct mode vs Gateway mode

**Direct mode** (`useGateway: false` or gateway credentials absent): each model connects directly to the provider's API endpoint using a provider API key selected round-robin from the vault.

**Gateway mode** (`useGateway: true` + `gatewaySecret` + `gatewayId`): all requests go through the Cloudflare AI Gateway endpoint. The gateway is OpenAI-compatible, so all providers are exposed as a single OpenAI endpoint with the model prefixed by the provider name (e.g. `groq/llama-3.3-70b-instruct`). Two authorization headers are sent:

- `cf-aig-authorization: Bearer <gatewaySecret>` — Cloudflare gateway token
- `Authorization: Bearer <provider-api-key>` — provider key selected from the vault

### Vault format

The vault is a JSON file (`ai.json`) encrypted with:

```bash
openssl enc -aes-256-cbc -a -pbkdf2 -iter 100000 -salt \
  -in ai.json -out ai.json.enc -pass pass:"${SECRET}"
```

Each provider entry in the vault can carry `gatewayEndpoint` and `gatewayModelPrefix` to control gateway routing per provider.

### Key rotation

- A **🔑 Chg. Key** button appears in the chat input toolbar whenever a vault model is selected.
- Clicking it rotates to the next available key for that provider.
- A VS Code command `Continue: Rotate KeypoolLive API Key` is also available in the Command Palette.
- Keys that return 401/403/429 errors are automatically placed on a 15-minute cooldown and skipped in the rotation.
